# Agent Note: 随机演练要断言它所依赖的那个分布

Status: implemented

[English](2026-09-12-crash-campaign-asserts-its-own-distribution.md) | 中文

## Problem

P4-12 的崩溃演练(`packages/action/action-ledger/tests/fault-matrix.spec.ts`)是一条 acceptance 条款的直接证据:10,000 次随机崩溃中零重复外部副作用,计数落在一个假的外部服务上。它用 `random = (random * 1_103_515_245 + 12_345) % 2_147_483_648` 驱动崩溃点。

JavaScript 把那次乘法按双精度求值。从第二次迭代起乘积就超过 2^53、低位丢失,取模只会得到大的 2 的幂的倍数——于是 10,000 次迭代里抽到的崩溃点有 9956 次是 `none`、43 次 `after-reserve`、1 次 `after-send`,`after-receipt` 一次都没有。而且几乎每个 key 在前 250 次尝试内就到了 `confirmed`,所以少数真正抽中的崩溃点打在已落定的记录上,拿到 `duplicate` 就在 `throw` 之前返回了。演练断言零重复与 250 次提交,而这两条对「10,000 次干净尝试」同样成立。

套件里没有任何东西能抓住它。每一条断言都是关于**结果**的——没有重复、250 次副作用——而结果断言会被一个从未真正做过的实验满足。

## Decision

抽取改用 `Math.imul`,它把乘法留在 32 位里,也就是这个生成器被定义的那套算术;并取结果的**高**位。

高位是读者最容易跳过的那一半,而量出来的数据说明它不是可选项。用 `Math.imul` 却取低位时,生成器抽出的是 `23012301…`——LCG 的低位周期极短——对 250 个轮转访问的 key 来说,这让**每个 key 永久看不到四个崩溃点中的两个**,而聚合直方图恰好是每个点 2500 次。

所以这条用例对它自己的生成器断言两件事:每个崩溃点的下界,以及每个 key 都见过每个崩溃点。用下界而不是精确直方图,因为断言关心的是「生成器频繁到达每个点」,而精确计数恰恰是四周期能给出的东西。

每个 key 的每次尝试现在递交**下一个**代,因为重启会取一个新的 lease epoch;重复同一个代会让每次重试都成为自己的对等方,于是演练量的是一个会拒绝的账本,而不是一个会恢复的账本。

旁边还加了第二次演练:同样 10,000 次尝试,全程 unfenced。它仍然让每个副作用恰好提交一次,而这正是重点:崩溃重试的去重来自重启从磁盘上读到的 `sent` 状态,不来自围栏。unfenced 放弃的是**并发**排他性,而这件事顺序执行的演练量不了——那里从来没有一个活着的对等方可以与重启混淆——`store.spec.ts` 的双进程用例才是量它的地方。

## Alternatives considered

**断言精确直方图。**否决,因为这恰好是坏掉的生成器能通过的断言:取低位的版本正好是每个点 2500 次。下界说出演练真正需要的东西——每个崩溃点都被频繁到达——而不钉死一个任何重新播种都得追着改的数字。

**只断言聚合分布。**这是第一版,而它被四周期满足。按 key 的覆盖率才是把均匀生成器与短周期生成器分开的那条:周期造成的缺陷不是总数偏斜,而是每个 key 自己历史里的盲区。

**用一个库的 PRNG 替掉这个 LCG。**否决:为了每次抽四个取值引入依赖,而且它解决不了两个缺陷中的任何一个——一个正确的生成器若被从低位使用,照样会以同样方式循环。读者必须理解的修复是算术与取位,这两件事在这里四行之内都看得见。

**用时钟播种,让每次运行探索新路径。**否决,理由与演练最初写下时相同:无法以相同方式重跑的演练会把一次失败变成「那是哪一次运行」的故事。

**不动演练的结果断言,另加一个生成器单测。**否决。生成器单测通过的同时,演练仍可能用着另一套抽取;这条断言属于那条证据依赖它的用例本身,在那里它每次运行都会被重新量一遍。

## Consequences

这个文件现在跑两次 10,000 次尝试的演练,在 load average 约 36 的主机上耗时 37.8 秒,对应用例 120 秒的超时。这个超时被刻意没有抬高:同一条演练在安静的主机上是 9 秒,而一台高负载的开发机是环境读数,不是套件的属性。

以后若有改动把抽取弄坏,会在分布上失败,而不是悄悄产出一个不崩的演练。这就是值得留下的一般形态:当一条测试的证据依赖一次随机实验真的覆盖了它的空间时,这个覆盖是一条断言,不是一个假设。

这次演练第一次对每个 key 都跑过全部四个崩溃点,所以它现在才真正是它一直声称的那条条款的证据。它开始真的崩之后并没有暴露新缺陷——零重复与 250 次提交依然成立——而这正是这个 epic 断言过、却还没挣到的那个结果。
