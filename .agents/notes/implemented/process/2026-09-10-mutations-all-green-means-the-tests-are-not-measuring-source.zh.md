# Agent Note:变异全绿而探针沉默,说明测试量的不是你的源码

Status: implemented

[English](2026-09-10-mutations-all-green-means-the-tests-are-not-measuring-source.md) | 中文

## 问题

对一个新包的事务测试跑了三个变异——把生产库就地迁移而不是迁进隔离区、切换时直接覆盖 live 目录而不是先移开、health 检查失败只报错不回滚。**三个全部通过**。每次都核对过,变异文本确实在文件里。

在被变异函数的开头放探针,**一个字都没打出来**。测试 import 的是 `@deepseek-ai/dsh-plugin-migrations/transaction`;这个子路径在 `tsconfig.base.json` 里**没有别名**,于是源平面解析不到,vitest 跑的是先前 `tsc -b` 产出的 `lib/`。**在改源码的同时,套件量的是构建产物。**

这正是仓库那条"源平面与产物平面永不混"以**不留错误**的方向失效:缺一个别名不会报错,它会解析到别处去。

## 决定

**一个本该变红却没红的变异有三种可能原因,而且可以按固定顺序区分。** 记下来是因为其中两种早已知道,第三种此前没有:

1. **套件弱**——断言观察不到变异改动的东西。同一批里有两条属于此类:一条父子预算用例的两个读数都得 3 次请求;一条超时行的测试 adapter 把 `status` 默认成 503,于是把 503 测了两遍。
2. **变异体等价**——那处改动不可能改变行为。此前已记过一次:嵌套运行的准入变异重建了一个与被替换者相等的对象。
3. **测试根本没在跑被变异的代码。** 新增。**它从外面看与 (2) 一模一样**,只有探针能把两者分开。

**诊断手段就是探针,而且很便宜。** 在被变异函数开头放一句 `appendFileSync`,跑一条用例。**沉默即意味着测试从未到达那个文件。** 这件事要在**推敲断言之前**做,因为 (3) 会让一切关于 (1) 的结论作废。

**探针不要用 `console`**:本仓库的 vitest 对通过的测试不转发 console 输出,那里的沉默什么都证明不了。

**修类不修实例。** 缺失的那个别名是同类第五次;生成器现在会为每个包 `exports` 发布的子路径**自动发出别名**,并在任一子路径未被映射时**拒绝**。

## 考虑过的替代方案

**把存活的变异当作"代码本来就对"的证据。** 探针一响这条自然被否,但值得点名:**正是这种读法会让一套空转的用例看起来很强**,而且每次都摆在那里可选。

**手写补上那一个别名。** 前四次就是这么做的。每次在局部都正确,并且把第六次留给了后来人。

**要求所有测试改用相对路径 import。** 否决:按包名 import 是仓库惯例,且它走的正是消费者会走的那条解析。缺陷在别名,不在 import 风格。

## 后果

换来:发布了却没有别名的子路径,现在是**生成器失败**,而不是悄悄改指 `lib/`;并且"变异变绿"有了成文的诊断顺序。

代价:`PackageAlias` 多了 `subpaths` 字段,生成器自己的用例把这条推导钉住。一个子路径若由构建产物而非源码模块支撑,会被 `src/<name>.ts` 这道检查排除——这是刻意的(给它发别名会指向一个不存在的文件),但也意味着这类子路径保持原有的解析方式。
