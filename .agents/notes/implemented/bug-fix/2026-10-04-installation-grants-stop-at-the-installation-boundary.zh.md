# Agent Note：安装授予止于安装边界

Status: implemented

[English](2026-10-04-installation-grants-stop-at-the-installation-boundary.md) | 中文

## 问题

`installationWildcardGrants` 在层的包目录等于从安装锚点按 Node 查找规则找到的目录时，把安装的通配授予给这一层。这个查找会走遍直到文件系统根的每个 `node_modules` 目录，比较的又是写出来的路径。安装不带某个被授予的名字时，查找会走到安装之上的 `node_modules`（例如用户主目录里的那个），放在那里的同名包就拿到了授予（gate3 2026-10-04T06:09:59Z，弱点 1）。同样按路径比较，还会把经两条路径到达的同一个目录当成两份副本。

## 决定

- 安装自己的副本只在安装之内查找：上限是安装真实路径之上最外层的 `node_modules` 目录；安装不在任何 `node_modules` 之内时（源码检出），上限是它自己的 `node_modules`。安装不带的名字没有副本，也没有授予。
- 层的目录与安装的副本按真实路径比较。上限约束的是包被找到的位置，不是它的真实路径：工作区链接包的真实路径在所有 `node_modules` 之外，而安装是信任根，安装内的链接是安装自己的选择。

## 考虑过的替代方案

- **要求真实路径本身落在安装之内。** 源码检出把每个工作区包从 `apps/cli/node_modules` 链接到 `packages/`，不在任何 `node_modules` 之内，从源码运行时出厂层会失去授予。
- **按记录的摘要比较文件内容。** 安装是信任根，没有记录自身包的摘要可供比较。

## 后果

- 授予表里的层若是从安装之上解析到的，就拿不到授予；在 `enforce` 下它会因通配在挂载前被拒。
