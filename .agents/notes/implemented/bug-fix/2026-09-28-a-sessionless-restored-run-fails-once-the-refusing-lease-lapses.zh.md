# Agent Note: 会话已丢的恢复 Run，在拒绝它的租约过期后判为失败

Status: implemented

[English](2026-09-28-a-sessionless-restored-run-fails-once-the-refusing-lease-lapses.md) | 中文

## 问题

重启之后，Run 插件把会话已全部不存在的非终态恢复 Run 判为失败（P4-05 acceptance[2]）。它只在会话持久化可用时查一次，遇到存储拒绝租约的 Run 就跳过。重启若早于已死前任的租约过期，这个 Run 就一直停在非终态，直到下一次重启（盲审 2-1；先红 A-568）。同一次检查在第一个抛错的 Run 处就停下，并且不放已经拿到的租约（2-3）。另外，Run 的结束判定只看插件的失败表，所以经 `runs.advance` 结束为 `failed` 的生命周期被记成了 `succeeded`（2-4）。

## 决策

- 租约被拒的 Run，在拒绝它的租约到期后一毫秒再查一次（租约在到期那一刻仍被持有），存储说不出到期时间时，就在一个租约期之后再查（`packages/run/run/src/index.ts`）。每次检查都重新读 Run 的状态与它的会话，拆卸时清掉尚未执行的检查。
- 每个 Run 各查各的：出错记日志，继续查下一个；为写入拿到的租约在 `finally` 里释放。
- 未恢复的错误是 Run 最后报告的活动，或者 agent 的生命周期已经以 `failed` 结束，结束判定就是 `failed`。

## 已考虑的替代方案

- **按固定间隔反复检查所有恢复的 Run。** 这要多一个可调参数，而拒绝它的租约自己的到期时间已经说明答案何时可能改变。
- **不拿租约就把 Run 判为失败。** 租约仍有效的在线持有者会失去它的 Run。

## 后果

- 一直在续约的在线持有者保住它的 Run；每次看到的到期时间都会再排一次检查。
- 开启者的会话已不存在、而名下子级的会话还在的 Run，不会被判为失败，尽管只有开启者的会话能继续它（`adoptable`）。
