# Agent Note：安装按盘上数据判定，而不是按说明符

Status: implemented

[English](2026-10-04-an-install-judges-the-data-on-disk-not-the-specifiers.md) | 中文

## 问题

`dsh plugin` 原先只有在两个条件都满足时才启动数据迁移：插件的包说明符在 pnpm 运行前后的 profile manifest 之间变了，而且新版本声明了迁移。有几种安装会绕过它。卸载后重装没有之前的说明符。降级会让旧代码跑在新数据上。新代码可能在说明符不变的情况下进来。盘上有数据却什么都没声明的插件会被跳过。每一种都让某个版本跑在不是为它写的数据上（B-711b 1-3；P1-10 must[0]、acceptance[0]）。

## 决定

- Plugin Manifest v2 新增 `dataSchemaVersion`：一个版本期望其唯一数据存储所处的 schema 版本。它是非负整数；版本声明了迁移时，它必须等于迁移能到达的最高版本。
- pnpm 运行、来源校验之后，任何迁移之前，CLI 读出每个已安装插件唯一数据存储上标记的版本。存储的 domain 名就是它的存储单元名，所以读取时不用运行插件代码。读出的版本再与该版本期望的比较。
  - 数据较新（降级）就撤销安装，拒绝信息写明插件、存储与两个版本。
  - 存储所属版本没声明版本、数据较旧而版本没声明能把它前移的迁移、存储读不出来，也都撤销安装。
  - 数据较旧、版本的迁移能把它前移的，加入升级，说明符没变也一样。
- `judgeDataVersion` 是纯判定；`judgeInstalledDataVersions` 把它用在每个已安装插件上。

## 考虑过的替代方案

- **保留说明符触发，只补上重装的情形。** 降级与同说明符下的新代码仍然不受判定。
- **加载每个插件的代码来读它的单元描述符。** 这会在安装被判定之前就运行代码，而没声明迁移的插件本来就不带可加载的模块。

## 后果

- 新数据上的降级在任何迁移代码加载之前就被拒绝，pnpm 把之前的包放回去。
- 盘上有数据的插件必须声明 `dataSchemaVersion` 或迁移，否则安装被拒。
- 未覆盖：逐条记录存放的数据存储没有单元级的版本标记，所以不受判定；它的记录按版本自愈，升级本来也不碰它们。有多个数据存储的插件在这里也不受判定。
