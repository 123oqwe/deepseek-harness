# Agent Note: forget leaves a tombstone and clears the recall projection; supersede, merge and erase reach the index

Status: implemented

English | [中文](2026-09-26-memory-third-slice-lifecycle.zh.md)

## Problem

P6-03's third slice owes `must[3]` (support merge, supersede, forget, export and right-to-erasure, and propagate to the index), `acceptance[1]` (after `forget` the store, index, cache and projection clear within an SLA and a compliant tombstone is left) and `acceptance[2]` (export carries a record's source and conflict status). Before this slice `forget` physically deleted a record and left nothing, `export` returned neither provenance nor status, and the seam had no `supersede`, `merge` or `erase`. The `decideCrossScopeMerge` and `recordConflict` decisions existed but nothing called them.

The projection clause is the subtle one. `@deepseek-ai/dsh-memory-context` recalls records into a step's request as a durable `snapshot`-form user message. Once a record a step recalled is forgotten, the store, the default search and a second reader stop returning it — but the earlier recall snapshot stays in the session's history and rides into every later request, so the forgotten content keeps reaching the model. Clearing the store is not clearing the projection.

## Decision

`ctx.memory` gains the verbs on the seam and all three providers:

- **`supersede({ principal, scope, id, supersedes })`** — the newer record gains a `supersedes` relation to the older, the older is marked `superseded`; the default search returns only the newer, `export` keeps both (must[1] — a conflict never overwrites).
- **`merge({ principal, from, into, authorization? })`** — `into` gains a relation to `from`, which is marked so only the survivor is searched. A cross-scope merge with no `authorization` naming both scopes is refused with `MEMORY_MERGE_NOT_AUTHORIZED` before either record changes, through the existing `decideCrossScopeMerge`.
- **`forget`** now removes the record's content and leaves a `{ id, forgottenAt, forgottenBy }` tombstone that carries none of it; `export` lists the tombstones the access context may see.
- **`erase({ principal, tenantId, subject })`** — right-to-erasure — forgets every record about the subject in the tenant, in any session or workspace; other subjects and other tenants are untouched.
- **`export`** records now carry `provenance`, `status` and `relations`; `query`/`get` keep the bare view.

The **projection clears in `@deepseek-ai/dsh-memory-context`**, not in the loop. A recall is that consumer's own `snapshot`-form user message, but `Session.deriveMessages` folds every appended surface node with no producer collapse, so `@deepseek-ai/dsh-llm`'s `ContextForm` 'snapshot' does not by itself drop an earlier recall from the request — and the agent-loop invariant (`invariant.ts`) asserts the request's messages equal `deriveMessages`, so a stale recall stays until its surface node is removed. The consumer therefore realizes the snapshot itself, the way `RuntimeContextProjection` realizes the system prompt: when a step's recall differs from the one still on the surface, it shadows the earlier recall's node with an empty `system/message` — a `replace` that derives to no wire message, so the node is removed rather than left as an empty user turn — and appends the new recall at the tail; a step that recalls nothing but has an earlier recall shadows it and appends none. Whether an outstanding recall exists, and its seq, is read from the model-visible **surface** (`outstandingRecall`), not from per-plugin-instance memory or a cleared marker in the log, so a recall already shadowed is not re-found, a resume that rebuilt the surface from the log sees exactly what the live session did, and a step whose recall is unchanged emits no event at all. A session this consumer never recalled on emits nothing.

The durable document gains an additive top-level `tombstones` list **without a version bump**: it is not a per-record field, so a version-3 document that predates it is complete — it forgot nothing — and reads back with no tombstones rather than a fabricated value.

## Alternatives considered

- **Rely on the producer-snapshot supersede alone — append a newer (or cleared) snapshot and trust `ContextForm` 'snapshot' to drop the earlier one.** Tried first (v1/v2) and rejected: `deriveMessages` folds every appended node, so both the old and the new snapshot reach the request; the supersede is a surface-node contract that only a `replace` realizes, not an assembly-time collapse. This slice replaces that append with a `replace` that shadows the earlier recall's node.
- **Filter the forgotten recall after assembly — in `buildRequest`, or on `llm/stream`.** Rejected: `invariant.ts` asserts the request's messages equal `session.deriveMessages()`, so any post-assembly filter desynchronizes the request from the durable derivation the log reconstructs; and a memory-specific filter in the generic loop is the wrong layer. The only invariant-respecting point is the surface, which `deriveMessages` folds — so the fix is a surface `replace`, not a request rewrite. This is B-class Q23's option (a), which the user chose.
- **Rewrite the session log to drop the forgotten recall (Q23 option (c)).** Declined by the user in favour of (a): the log is append-only history, and rewriting it would erase the record that the model DID see the recall before the forget. The shadow is an appended `replace` event; the earlier recall event stays in the log.
- **Narrow the clause so an already-sent recall need not be cleared (Q23 option (b)).** Not this lane's to take: narrowing a frozen clause is the user's decision.
- **Shadow with an empty `user/message` or `assistant/message` instead of `system/message`.** Not possible: a `user/message` always derives, so an empty one still reaches the request as an empty user turn; an `assistant/message`'s `SurfaceIntent` forbids `sourceEventSeqs`, which a `replace` must carry. `system/message` empty is the one null-deriving surface type a `replace` may carry provenance for, and `RuntimeContextProjection` ignores empty system nodes, so it does not perturb the system prompt.
- **Bump the durable format version for `tombstones`.** Rejected: the version bumps guarded per-record fields an old record lacks and cannot be read without inventing; a new top-level list is absent-means-none, and `durable-provider.spec` asserts the written version is 3.
- **Reuse `record.ts`'s `recordConflict` for supersede/merge.** Not possible directly: it is typed for P6-02's canonical `MemoryRecord`, and the providers store the provisional `ScopedMemoryRecord`; a local `supersedeInto` encodes the same no-overwrite rule for the stored shape.

## Consequences

- A-512's measured state, carried here rather than filed separately: this build has no persistent memory index, cache or session projection as separate objects. `acceptance[1]`'s "index" is the `query` scan over the store, its "cache" is a second provider instance over the same directory, and its "projection" is memory-context's recall snapshot — so clearing the store clears the first two, and the memory-context change clears the third. No new persistent index was introduced.
- The projection clear reads the outstanding recall from the surface and shadows its node with an empty `system/message`, so both of Lane B's red-first cases (`P6-03.projection.composition.spec.ts`) close: a session recalled, forgotten, then RESUMED in a fresh process; and the same session taking one more turn whose task is whitespace, so its step has no query. `P6-03.lifecycle.composition.spec.ts`'s after-forget projection case closes the same way. Earlier attempts appended a cleared snapshot instead, which `deriveMessages` folded alongside the old one so the forgotten content still rode into the request; the `replace` removes the node. `memory-context-idempotent.spec.ts` adds the one behaviour this slice introduces: two turns recalling the same record leave exactly one recall and no shadow.
- Not covered, by construction: the session log still holds the pre-forget recall's original text (append-only history — the model DID see it then, and the `replace` is an appended event, not a rewrite); a request already sent before the forget carried the content and cannot be recalled; and a recall node already shadowed by compaction has nothing left for this consumer to shadow.
- No package.json or lockfile change: memory already peer-depends on `dsh-principal`, and memory-context on `dsh-llm`. The generated `tool-cordis` api-catalog projection goes stale on the new export shape and provider verbs and is left for the pipeline to regenerate.
