# @deepseek-ai/dsh-secrets-broker

[English](README.md) | 中文

## 概述

`CredentialRef` 指名一份存储的凭据。`SecretLease` 是这个引用为**一次使用**解析出的东西：一次绑定到 `Principal`、`ActionId`、`WorldId`、一条记录下来的用途和一个过期时刻的授予。`decideRedemption` 回答此刻这条租约能否兑付，要么给出凭据，要么给出它拒绝的那一个理由。

## 一条租约绑定什么

五项绑定是 must[0] 字面列出的那一组，每一项都指向一个已存在的主体：`Principal` 来自 `dsh-principal`，`ActionId` 来自 `dsh-action-manifest`，`WorldId` 来自 `dsh-execution-world`。为同一批事实另造一套词汇，只会让系统的两处对「这条租约是给哪个动作的」给出不同答案。

过期先于绑定被检查。一条已过期的租约，无论谁出示都以过期为由拒绝，因此拒绝不会告诉调用方「换个主体本来是能对上的」——那是一份他们已不再持有的授予的事实。

## 过期是关于时钟的事实

`effectiveState` 会把一条仍存为 `issued` 的记录在 `expiresAt` 过后读作 `expired`，无需任何清扫器跑过。这正是重放路径上过期租约不可用的原因：重放按定义就是没有清扫器跑过的那条路径。比较取 `>=`，所以记录下的那个时刻是第一个不可用的时刻，而不是最后一个可用的时刻。

## 用过即撤，世界停止亦撤

`afterRedemption` 把记录置为 `redeemed`，因此同一条租约再次出示会被拒绝（must[2]）。一个世界停止，就终结它内部的每一次授予，无论各条租约自己的过期时间如何——`revokeWorldLeases` 就是这个级联，作为记录与世界 id 的纯函数。

终态永不被改写。一条租约最先因何不再可用，就是审计留存的那个理由。

## 模型体验

没有模型可见面。本包只做判断；它不渲染任何东西，不新增工具、提示词或会话事件。不会为它花费 token，它也不参与 KV 缓存。

## 已知限制与延后工作

- **must[1] 的经纪式注入未建模。** 让密钥不经环境变量抵达一个世界，需要 `WorldSecretsSpec.posture: 'broker-only'`，而 `execution-world/src/local-provider.ts` 拒绝它：只有独立地址空间才守得住这个承诺。传输等那个形状定下来；本包给出的是授予。
- **acceptance[1] 的泄漏面不在这里覆盖。** 密钥是否不出现在 stdout/stderr、崩溃转储和会话日志里，是写出方的性质，不是租约的性质。尤其是会话日志一支，本树上没有脱敏接缝——`session-telemetry` 的 waterfall 覆盖的是发往后端的记录，且不带任何规则。
- **没有租约存储。** 记录是值；这里不持久化也不索引任何东西。租约的持久化归谁所有尚未决定，在传输方式选定之前写出的存储，很可能要随它重写。
